# MySQL Setup (Docker) — Flipkart Metadata

Temporary MySQL 8 server, run via Docker, for loading `flipkart_metadata.sql`
(generated by `flipkart_to_lightrag.py`) into a queryable database.

## 1. Prerequisites

- Docker installed and running (`docker --version`, `docker ps`).
- `flipkart_metadata.sql` already generated by running:

  ```bash
  python3 flipkart_to_lightrag.py
  ```

## 2. Start the MySQL container

```bash
docker run -d \
  --name flipkart-mysql \
  -e MYSQL_ROOT_PASSWORD=rootpass \
  -e MYSQL_DATABASE=flipkart \
  -e MYSQL_USER=flipkart_user \
  -e MYSQL_PASSWORD=flipkart_pass \
  -p 3307:3306 \
  mysql:8.0
```

Port `3307` (not the default `3306`) is used on the host to avoid clashing
with any local MySQL install.

## 3. Wait for the server to be ready

```bash
for i in $(seq 1 30); do
  docker exec flipkart-mysql mysqladmin ping -uroot -prootpass --silent 2>/dev/null && echo "MySQL is up" && break
  sleep 2
done
```

## 4. Grant the app user privileges (first run only)

```bash
docker exec flipkart-mysql mysql -uroot -prootpass -e \
  "GRANT ALL PRIVILEGES ON flipkart.* TO 'flipkart_user'@'%'; FLUSH PRIVILEGES;"
```

## 5. Import the data

The generated file uses `INSERT INTO`. A handful of source rows can share a
duplicate `sku_id` (the raw Flipkart `pid` column isn't perfectly unique),
so import with `INSERT IGNORE` to skip duplicate-key rows instead of failing
the whole import:

```bash
sed 's/^INSERT INTO/INSERT IGNORE INTO/' flipkart_metadata.sql > flipkart_metadata_ignore.sql
docker exec -i flipkart-mysql mysql -uroot -prootpass flipkart < flipkart_metadata_ignore.sql
rm flipkart_metadata_ignore.sql
```

If you know the source has no duplicate `sku_id` values, you can instead
import the file directly:

```bash
docker exec -i flipkart-mysql mysql -uroot -prootpass flipkart < flipkart_metadata.sql
```

## 6. Verify

```bash
docker exec flipkart-mysql mysql -uroot -prootpass flipkart -e \
  "SELECT COUNT(*) AS row_count FROM product_metadata;"
```

## Connection details

| Field    | Value                 |
|----------|-----------------------|
| Host     | `127.0.0.1` (or `localhost`) |
| Port     | `3307`                |
| Database | `flipkart`            |
| Table    | `product_metadata`    |
| User     | `flipkart_user`       |
| Password | `flipkart_pass`       |
| Root user | `root`               |
| Root password | `rootpass`      |

**Connection URL:**

```
mysql://flipkart_user:flipkart_pass@127.0.0.1:3307/flipkart
```

**CLI:**

```bash
mysql -h 127.0.0.1 -P 3307 -u flipkart_user -pflipkart_pass flipkart
```

## Table structure — `product_metadata`

| Column | Type | Notes |
|---|---|---|
| `sku_id` | `VARCHAR(64)` PK | Product identifier (`pid`, falls back to `uniq_id`) |
| `product_name` | `VARCHAR(512)` | Cleaned product title |
| `brand` | `VARCHAR(255)` | Brand (CSV column → spec lookup → first word of name) |
| `category` | `VARCHAR(255)` | Top-level category (from category tree, or keyword fallback) |
| `category_is_fallback` | `TINYINT(1)` | 1 if `category` came from the keyword fallback rather than the real tree |
| `subcategory_path` | `VARCHAR(512)` | Remaining `>`-joined category tree segments |
| `material` | `VARCHAR(255)` | Pulled from parsed specs, if present |
| `size` | `VARCHAR(100)` | Pulled from parsed specs, if present |
| `retail_price` | `DECIMAL(10,2)` | Original listed price |
| `discounted_price` | `DECIMAL(10,2)` | Sale price |
| `rating` | `DECIMAL(3,2)` | Product rating (NULL if unavailable) |
| `stock_status` | `ENUM('in_stock','low_stock','out_of_stock')` | Synthesized, seeded per SKU |
| `quantity` | `INT` | Synthesized total quantity, seeded per SKU: 0 if `out_of_stock`, 1–4 if `low_stock`, 5–50 if `in_stock` |

Not stored in this table: the free-form `specifications` dict (unbounded/nested,
lives only in the JSONL) and the product description text (lives in the
Markdown RAG corpus).

## Teardown

This container has no persistent volume — data is lost once it's removed.

```bash
docker rm -f flipkart-mysql
```
